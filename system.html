Capabilities (CAPABILITIES.md)

SpellBattle — Agent System Capabilities

A plain-English record of everything this setup does, so you never have to remember it. Keep this file updated whenever the workflow changes — add a line to the Changelog at the bottom. The dashboard reads the crew and the gates from the live config, so those stay accurate on their own; this file is the human-readable "why" and the place for everything else.

At a glance — who owns what

  • You own testing. Agents never run the game, enter Play Mode, or run builds. When something

is ready, they hand it to you with notes on what to check.

  • You own visuals. Scenes, prefabs, UI, sprites, materials, animations, shaders — agents

propose changes and wait; they don't apply them on their own.

  • Agents own the backend. Gameplay logic, systems, bug-fixing, refactors, problem-solving —

they work proactively here, within the design rules in CLAUDE.md.

The crew (subagents)

  • competitor-researcher — researches the market, competitors, monetization, retention, genre

trends. Can search the web and write to docs/research/. Read-only on your code.

  • unity-code-reviewer — reviews C# changes against your conventions and load-bearing rules

before you commit. Reads code and git; never runs the game.

  • game-design-keeper — reasons about design/balance within your fixed constraints and keeps

TODO.md consistent. Reads and writes design notes.

  • roadmap-keeper — keeps .claude/state/roadmap.json current as tasks start, finish, or block;

drives the visual Roadmap page and the "Resume here" view.

  • test-runner — runs automated pre-flight checks (compile, Unity tests, lint) and reports

whether a build is worth your hands-on test. Never plays the game for you.

Add a new one anytime: /agents in Claude Code, or drop a markdown file in .claude/agents/.

What needs your sign-off (everything else runs automatically)

You get an Allow/Deny prompt (terminal or phone) for:

  • Commits & pushes — git commit, git push.
  • Design docs — TODO.md, CLAUDE.md, DESIGN.md, anything in docs/design/.
  • Visuals — scene (.unity), .prefab, UI (.uxml/.uss), .mat, .anim, .controller,

.shader, .spriteatlas files.

  • Running the game/tests — anything that looks like a Unity test/batch run.
  • Anything not yet trusted — any shell command not on the allow list also asks (safety net).

Blocked entirely: rm -rf, force-push, git reset --hard, reading .env.

Note on visuals: file-level gates above catch direct edits to scene/art files. Once the Unity MCP bridge is connected, the editor-level visual actions (moving objects, assigning sprites in the inspector) are MCP tool calls — share those tool names and we'll add precise gates for them too. Until then, the standing instruction in CLAUDE.md keeps agents proposing rather than applying.

The dashboard

A small static site in the dashboard/ folder, regenerated after each agent turn and auto-refreshing every 20s. Open dashboard/index.html (or the dashboard.html redirect at the project root) and leave the tab up. Pages, reachable from the menu on every page with a back-to-overview button:

  • Overview — a "Ready to test" banner, a "Resume here" briefing, the menu, pending approvals,

open questions, build progress, ownership.

  • Roadmap — visual phase track + task-level breakdown (status + priority, high-priority and

blocked items highlighted).

  • Inbox — everything waiting on you in one place: changes ready to test, pending approvals,

open questions, and approval history.

  • Research — the full text of every writeup in docs/research/, aggregated on one page.
  • Activity — the complete event timeline, grouped by day.
  • System — the crew, commands, what's gated, ownership, and this capabilities doc.
  • Commits — full git log for the current branch.
  • Design — load-bearing rules, build progress, and open/done TODO items.

Continuity (for a stop-and-start project)

  • The roadmap-keeper keeps the roadmap accurate; the Resume here panel and /resume give you

a plain-English "where was I" whenever you come back.

  • Agents log every meaningful change; the Ready to test banner and /whats-new show exactly

what to play-test, with gameplay changes highlighted. /tested clears it.

  • Agents surface precise questions to the Inbox instead of guessing; answering them records

the decision so it's never re-litigated.

  • Deferred ideas (marketing/branding agents, an email/feedback assistant) are parked in

FUTURE.md so they're remembered without cluttering the work.

Remote review

Approve/deny from your phone via CCGram (Telegram buttons) or Claude Code's official Remote Control + Channels. Only the gated actions above will ping you. See REVIEW-AND-DASHBOARD.md for setup.
